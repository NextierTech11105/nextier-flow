Set up a new workspace

Every workspace gets its own Apify account and key. The runs, the bill and the data stay with the workspace they belong to.

Create the Apify account in the client's name, with the client's card.
Set the monthly usage limit in Apify → Billing → Limits. Pick it on purpose. It's the ceiling for every run and every schedule on the account.
Copy the API token from Apify → Settings → API & Integrations.
Paste it into the workspace's Connect Keys in Nextier. The Apify slot is being added; until it ships, keep the token in the Apify account. Never send it by text or email.
Run one small test job (50 rows) and check the receipt. Then the workspace is live.

The run SOP, every job, in this order

Right workspace, right keyThe job runs on the key of the workspace that will own the leads. A run bills whichever account starts it. A client's job never runs on Nextier's key, and the other way round.
Check the walletOpen the usage page: spent this month against the limit. If this job could cross the limit, raise the limit first. Only the account owner does that.Why: when an account hits its limit, every run and every schedule on it stops until the next cycle. We had a daily schedule go dark for weeks this way.
Read the job descriptionOpen the actor's input fields and its sample output before the first run. Confirm it returns the field you're paying for, usually the phone.Why: an actor quietly ignores fields it doesn't know. One of our daily jobs was wired with field names its actor doesn't read, and it never produced a row.
Count firstGet the size of the market before buying it: a free count where the site has one, or a sample of 50 to 500 rows.
Cap the pay and say the numberEvery run gets a hard row cap, plus a maximum charge on actors that bill per event. Before pressing Run, say the dollar figure out loud: rows × price.
Run, then read the receiptOnly a run that SUCCEEDED gets loaded. FAILED, ABORTED and TIMED-OUT runs keep their receipt and load nothing.
Keep the raw data, then loadSave the raw results first. Then clean them up: one lead per phone, stable ids so a re-run never doubles anyone. Do a dry run, then apply, into the workspace that owns the job.Why: raw results on a basic plan are deleted after about a month. Anything worth keeping is saved or loaded inside that window.
Write it where it gets workedResults go onto the lead in the same run, and the bucket shows the new count.Why: a phone that sits in a side file is invisible. It happened: five owners were traced, and nobody could see the phones until they were written onto the leads.
Check before anyone dialsDo Not Call check on every phone. Mobile first. Remove anything listed with an agent right now. Apply the client's own rules, like no foreclosure leads.

Hiring an actor

The Apify Store has thousands of actors, and many do the same job. Pick one with this scorecard, then test it before trusting it.

Pays on hitsCharged per result found; empty lookups freeCharged per search whether or not it finds anything (and that's the bulk of the cost)

A free route beats a paid actor when the data is the same. Reading Craigslist ads directly found the same phones as the paid actor: on 2,609 ads, the actor's only extra numbers were 11 ZIP codes.

The rules

New only, every dayFor daily feeds, use monitoring mode or a saved storage name, so each run returns only listings not seen before. Don't re-buy the whole market every morning.
One catalogEvery actor in use is listed once, with its id, inputs, price, role and owner. Nobody hard-codes a new actor in a side script.
Named schedules with ownersOne schedule per job, named workspace · job · how often, with a person responsible. A schedule that stops running is the first sign the wallet is empty.
No live listings in pursuitListing actors exist to remove what's on the market and to find what expired. A for-sale-by-owner listing has no agent and is the one exception.
Found phones aren't verified phonesA phone from a people search or a list gets the Do Not Call check, is ranked mobile first, and moves to the next-best phone on a wrong number.
Raw firstWhen an actor sends results into Nextier, the raw payload is stored before anything is parsed. If the raw is lost, the run is lost.
Tenant wallsLeads load into the workspace that paid for the run, and only that workspace. Nothing is copied across.
Tokens stay secretA token never goes in a page, a script, a text or an email. It lives in Connect Keys.
Pace the free readsReading a site directly is free but polite: about one request a second. A hard crawl gets the address blocked.
Stop a runawayApify → Runs → Abort. Charges stop with the run. Then find out why before re-running.
Volume isn't the limitAn account runs many jobs at once. What limits a workspace is its monthly limit, so set it on purpose and check it weekly.
Leads in, sends gatedA run can find and load leads. Nothing gets texted or called in bulk without the owner's go.

Checklists

Daily · 5 minutes

  • Every schedule ran on time
  • No FAILED or ABORTED runs left unexplained
  • New rows are on leads, and the bucket counts moved
  • Phones flagged Do Not Call are blanked

Weekly · 15 minutes

  • Spent so far against the monthly limit
  • Cost per phone found, per actor
  • Hit rate per actor; one that's slipping gets tested against another
  • Listed-now check ran; live listings left pursuit

Monthly · 30 minutes

  • Remove actors nobody used
  • Catalog matches what's running
  • Tracing sized to callers, not to the list
  • Limit set for next month, on purpose

Red flags: stop and fix before the next run

A run SUCCEEDED with 0 rowsUsually wrong input field names. Read the job description again.
The cost came in above the number you saidThe cap was missing, or the actor charges per search. Fix the cap before the next run.
A schedule's last run is older than its cadenceCheck the wallet first. A limit hit stops everything on the account.
Phones exist in a file but not on leadsNobody can call them. Load them the same day.
Rows from the wrong county or stateMatching crossed a line. Add the county check before loading.
A property listed with an agent in a pursuit bucketTake it out of pursuit and find out how it got in.
The same person loaded twiceThe ids aren't stable. Fix the dedupe before re-running.
